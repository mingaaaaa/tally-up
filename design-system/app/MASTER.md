# 记高一筹 App 设计规范

App 延续暖日金的浅色视觉。底部导航和单手记账是手机端的交互基准。设计按 iOS 和 Android 的系统能力表达，组件和单位随平台映射。App 技术栈仍待项目确定。

## 色彩与材质

沿用[跨端基础色](../web/MASTER.md#跨端基础色)。用暖灰做页面底，纸白承载流水与表单，结余卡使用浅蜂蜜色和深色数字。收入用灰蓝与正号，支出用陶土色与负号。主要按钮用陶土实底配白字，聚焦、按压、禁用和错误状态各有可辨认的变化。

- 结余卡可使用共享的浅蜂蜜渐变。保持静态日光感，按压用小幅亮度变化或平台按压反馈。边线轻、阴影低，金额下方使用同一表面。
- 系统支持半透明材质时，可以在底部导航或浮层边缘使用浅层模糊。密集列表、字段和数字区域使用纸白实底。系统减少透明度时，导航和浮层也使用纸白实底。
- 图标在同一端保持一致的线宽、大小和含义。底部一级导航同时显示图标与短标签。仅图标的按钮提供读屏名称。

## 屏幕与导航

| 项目     | App 规则                                                                                                                                    |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 一级入口 | 底部导航使用「总览」「流水」「分类」。各入口保留可见标签、明确选中状态以及当前页面的标题。遵循平台的系统返回方式。                          |
| 单手记账 | 总览和流水在安全区上方显示「记一笔」。它属于操作区，和底部页面切换用间距区分。结余卡内快捷入口可直接带入收入或支出。                        |
| 内容顺序 | 总览依次显示期间和结余、收入与支出、趋势、最近流水。完整流水和分类分别在对应入口展开，进入某条记录后从系统返回恢复当前列表位置和筛选。      |
| 排版     | 手机使用单列，内容左右留白 `16` 逻辑单位，区块间距常用 `16–24`，内部间距以 `4 / 8 / 12 / 16` 为主。常规面板圆角 `8`，系统弹层沿用平台外形。 |
| 安全区   | 底部操作与导航避开手势区，列表底部预留对应空间。键盘升起时让当前字段和保存动作处在可达区域。横屏或大字模式下允许表单继续滚动。              |

## 字体与触控

使用平台默认中文系统字体与等宽数字特性。尺寸在 iOS 读作 pt，在 Android 文本读作 sp，间距和组件尺寸读作 dp。下面的字号是默认层级，跟随系统文字缩放。

| 层级           | 默认尺寸 | 使用位置             |
| -------------- | -------- | -------------------- |
| 页面标题       | `24`     | 总览、流水、分类     |
| 结余金额       | `34`     | 本月结余             |
| 分区或表单标题 | `18–20`  | 走势图、列表、记一笔 |
| 正文和字段     | `16`     | 交易名称、录入控件   |
| 次要标签       | `13–14`  | 日期、分类、支付方式 |

可触控区域在 iOS 至少为 `44 × 44pt`，Android 至少为 `48 × 48dp`。金额和图表标签优先完整显示，过长的交易名称与支付信息可自然换行。金额统一用人民币符号、千分位和两位小数，流水行用正负号表达收支。 [Apple 无障碍指南](https://developer.apple.com/design/human-interface-guidelines/accessibility) · [Android 触控目标指南](https://developer.android.com/guide/topics/ui/accessibility/apps)

## 录入与组件

| 场景       | App 规则                                                                                                                                                                   |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 记一笔     | 从底部弹层打开，空间不足时切换为可滚动全屏表单。初始焦点进入金额，用可输入小数的数字键盘。先确认支出或收入，再选相应分类，填写支付方式和可选备注。                         |
| 保存与取消 | 保存是弹层的主操作，默认标题随收支变为「保存支出」或「保存收入」。提供明确的取消与关闭。校验错误贴近字段，保留草稿并把焦点引到第一个错误。保存后更新对应日期的流水和总览。 |
| 流水       | 按日期倒序，日期行同时显示当日小计。交易行左侧是名称与支付方式，右侧是有符号的金额，分类可放在二级文字中。搜索与收支筛选可以叠加，从结果返回时恢复条件。                   |
| 图表       | 「近 7 天」「本月」分段显示范围。轻点或拖动可以选一天，同时展示日期和金额。提供可读的数据摘要，使读屏用户也能查看选中日期的值。                                            |
| 分类       | 以分类列表的名称、金额和百分比为准。环形图突出最大分类的占比。屏幕较窄或字体放大时先保证列表完整，图表与文字可上下排列。                                                   |
| 状态       | 加载保留内容层级，失败显示具体说明和重试。首次无记录提供「记一笔」。筛选为空提供清除入口。提交处理中锁定重复保存并保留录入内容。                                           |

## 动效与无障碍

- 按压、选中等局部反馈使用约 `120–180ms` 的短过渡，弹层按系统交互节奏呈现。保持可见的取消、返回和保存按键，手势作为补充。系统启用减少动态效果时，内容直接更新或使用短淡入。
- 读屏顺序按标题、金额或字段、操作排列。验证 VoiceOver、TalkBack、动态字体与系统返回。图标、表单、选项和保存结果都有准确的读屏名称和状态。
- 普通文字以 `4.5:1`、大字和必要图形以 `3:1` 为对比度检查目标。色彩、收支符号和标签共同表达数据。按实际渲染表面检查模糊层与高光处的对比度。 [WCAG 2.2 对比度参考](https://www.w3.org/TR/WCAG22/#contrast-minimum)

## 验收

- 在小屏、常规手机和最大系统字号下检查金额完整性、触控目标和安全区。打开键盘后仍能编辑分类、关闭表单和保存。
- 走完总览到录入、金额校验、切换收支、保存、流水筛选和返回的路径。检查动态字体、读屏和减少动态效果三种设置。
- 开发 App 页面时先读本文件，再读 `pages/<页面名>.md` 中对应的页面差异。登录、后端和分析建议按单独确认的产品需求设计。
